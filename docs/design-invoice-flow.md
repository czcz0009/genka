# 納品書から仕入れ値を更新する流れの作り直し(設計案)

作成: 2026-10-27 / 状態: **1〜3段目は実装・公開済み(1段目 2026-10-27、2・3段目 2026-10-28 `ac6d1f6`)。4段目(名前の対応づけ)以降はこれから**。2・3段目で、税込・税抜・金額からの単価・二度読み・完了画面の原価率の一覧も入れた(テストは src/lib/invoiceOcr/ の各 .test.ts)
きっかけ: Mahiroが iPhone で納品書の読み取りを試し、読み取り自体は動いたが、その後の流れで店主が詰まる問題が複数見つかった。

## 0. 見つかった問題の原因(今のコードで確かめた結果)
| 問題 | 原因 |
|---|---|
| 1. 単位が換算できない(玉ねぎ1個55円 → 食材は g) | 換算は kg↔g、L↔ml などの決まった換算だけ(`convertUnitPrice.ts`)。「個→g」のような換算の根拠を持つ場所がDBに無いので、警告を出すだけで止まる |
| 2. 読み取り結果の欄が編集できない(灰色) | 登録先が「登録済みの食材」の行は、**食材名と単位をわざと編集できなくしている**(既存の食材の名前・単位を、読み取りから書き換えないため)。単価の欄は保存前なら編集できるが、「保存済み」になると全部の欄が灰色になる。灰色の理由が画面に書かれていないので、壊れているように見える |
| 3. カメラが直接開く・既存の写真やPDFが選べない | 写真の欄に `capture="environment"`(カメラを直接開く指定)が付いている。iPhoneではこれがあると、フォトライブラリやファイルの選択肢が出ない。`accept="image/*"` なのでPDFも選べない |
| 4. 単位に「本」は使えるのに「個」が使えないように見える | 「個」を弾く処理は無い(新規の食材の単位は自由入力)。考えられる原因は2つ: ①食材の新規登録の単位の**初期値が「g」**で、そのまま登録すると、**単位はあとから変更できない作り**(レシピの分量がその単位で入っているため)。②読み取り結果の画面で、登録済みの食材を選ぶと単位の欄が灰色になる。→ どの画面で「個」が使えなかったかを教えてほしい(再現を確かめる) |

## 1. 店主の流れ(受け取ってから単価の更新が終わるまで)
共通の考え方: **読み取る → 要確認だけ見る → まとめて確定 → 影響を見る**。自動では確定しない。

### 紙の納品書
1. 「納品書を読み取る」画面(ダッシュボードと食材一覧の両方に入口)で、**「写真を撮る」**を押す → カメラが開く → 撮る
2. 2枚以上あれば「もう1枚撮る」(最大5枚まで。1回の読み取りとして数える)
3. 「読み取る」 → 読み取り中(10〜30秒。止まったら日本語のエラーで選び直せる。実装済み)
4. 確認画面: 上に「要確認」の行、下に「いつもどおり」の行(まとめて折りたたみ)
5. 要確認の行だけ、その場で直す(登録先の食材、数量・単位・単価、換算「1個=◯g」)
6. 画面の下の「◯件を確定する」 → 完了画面(更新した件数と、原価率が変わったメニュー)

### 写真(すでに撮ったもの・LINEで届いた写真など)
- 1で **「写真から選ぶ」**(複数選べる) → 以降は同じ

### PDF(業者からメールで届いたもの・FAXをPDFにしたもの)
- 1で **「ファイルから選ぶ(PDF・画像)」** → PDFは最大5ページまで、3.5MBまで → 以降は同じ
- iPhoneでは「ファイル」アプリ、メールの添付は「共有 → ファイルに保存」してから選ぶ(手順を画面に小さく書く)

## 2. データの変更(マイグレーションが必要)
| 追加するもの | 中身 | 理由 |
|---|---|---|
| 表 `ingredient_unit_conversions`(0029) | 食材・仕入れの単位(個・本・箱・ケースなど)・その単位1つが食材の単位でいくつか(例: 1個=200g)・出どころ(店主が確定/目安から確定)・確定日時。食材×単位で1行 | 「1個は何g」を食材ごとに最初の1回だけ聞いて、次から自動で換算するため。1つの食材に複数の仕入れ単位(個・箱)を持てる |
| 表 `ingredient_name_aliases`(0030) | 店舗・食材・納品書の表記(玉葱・タマネギ等)・正規化した表記。店舗×正規化した表記で1行 | 名前の揺れを一度対応づけたら覚えるため |
| `ingredient_price_history` に列(0031、任意) | 出どころ(納品書/手入力/取り込み)・納品書の単位と単価・使った換算 | あとから「この単価はどう換算したか」を確かめられるように(単価の履歴の決まりはそのまま) |

- どちらの表もRLS: 持ち主の店舗の食材だけ(**食材の側の持ち主も確かめる**。点検16番の反省)。退会で一緒に消える(on delete cascade)
- マイグレーションは、何度実行しても同じ形・1つの do ブロック・最後に migration_log へ記録(今の決まりどおり)
- **目安の重さ**(玉ねぎ1個 約200g など)はDBではなくコードの中の一覧にする(店主が確定した値だけDBに入る)。一覧は「目安。必ず確認して確定」として扱う

## 3. PDFの読み取り方
- **おすすめ: PDFをそのままAIに渡す**(Claude APIはPDFを受け取れ、ページを画像としても文字としても読む)。FAXのPDFは文字の層が無い画像なので、文字だけを抜き出す方法では読めない。両方を1つのやり方で扱える
- 文字のあるPDFを文字だけで読む方法は、安いが、表の列のずれに弱く、FAXのPDFでは使えない → 今回は採らない
- 上限: **5ページまで・3.5MBまで**(サーバーの受け取りの上限4MBの内側)。中身の先頭が `%PDF-` かを確かめ、ページ数はサーバーで数えてから送る(pdfjs-dist は導入済み)
- 費用の目安(要確認: 公式の料金と、Haiku 4.5 がPDFを受け取れるかを実装前に確かめる): 1ページあたり入力1,500〜3,000トークン程度 → Haiku 4.5 で1ページ0.3〜0.5円程度、5ページで2〜3円程度。写真1枚(今)は1円未満
- PDF・写真とも、**保存しない**方針はそのまま(メモリの中で読んで捨てる)
- 読み取りの回数: **1回の読み取り(最大5枚・5ページ)で1回と数える**案。ページごとに数えるかはMahiroが決める

## 4. 画面の案(スマホ幅)
```
┌ 納品書を読み取る ──────────────┐
│ [📷 写真を撮る      ]  ← 大きいボタン │
│ [🖼 写真から選ぶ    ]                │
│ [📄 ファイルから選ぶ(PDF・画像)]     │
│ 選んだもの: [1][2][3] ×で外せる      │
│ [   読み取る(あと2回)   ]           │
└───────────────────────┘

┌ 読み取り結果(12件)─────────────┐
│ 要確認 3件                           │
│ ┌──────────────────┐ │
│ │ 納品書: 玉葱 1個 55円             │ │
│ │ 登録先 [玉ねぎ        ▼]          │ │
│ │ 換算   1個 = [200] g(目安)       │ │
│ │ → 0.275円/g  前回0.25円/g ↑10%  │ │
│ │ ☑この名前を覚える ☑換算を覚える   │ │
│ └──────────────────┘ │
│ (新しい品目・大きく変わった・換算が │
│   まだ・読み取りに自信なし の順)      │
│ いつもどおり 9件 ▼(前回比±10%未満) │
│   キャベツ 150円/個(前回150円) …    │
├───────────────────────┤
│ [ 12件を確定する ]  ← 画面の下に固定  │
└───────────────────────┘
```
- すべての欄(登録先・数量・単位・単価・換算)を、その場で直せる。灰色にする場合は、理由を一言書く
- 登録先は、検索できる選び方にする(食材が多いとき、長い一覧から選ぶのは大変)
- 「要確認」の条件: 新しい品目/前回の単価から±10%以上(アプリの仕入れ値アラートと同じ基準)/換算がまだ/読み取りに自信なし/数量×単価が金額と合わない/前回が未設定

## 7. ほかに店主が詰まりそうなところ
1. **読み取りの回数の上限が成功3回**: 週に何回も納品がある店では、すぐ上限になる。モニター期間の上限をどうするか(費用は1回1円未満)
2. **税込・税抜**: 納品書は「税抜の単価+消費税8%を別に記載」が多い。店舗の設定(仕入単価を税込で入れるか)と合っていないと、原価が8%ずれる。確認画面に「この納品書の単価は税抜/税込」を出し、店舗の設定に合わせて自動で直す案
3. **同じ納品書を二度読み取る**: 気づかずに二重に読み取っても、単価が同じなら害は無いが、回数を使う。納品日と取引先が同じなら「前に読み取った納品書かもしれません」と出す案
4. **新しい品目として登録した食材**: 歩留まり率100%・カテゴリなしで登録される。完了画面で「新しく登録した食材」を見せ、必要なら直せる入口を出す
5. **単価の記載が無い納品書**(金額と数量だけ): 今は単価が空になる → T-13のように計算して要確認にする
6. **保存した後に次に何をすればいいか分からない**: 完了画面で、原価率が変わったメニューと「今見直すべきメニュー」への入口を出す
7. **登録先の一覧が長い**: 食材が多い店では、ドロップダウンから探すのが大変 → 検索できる選び方
8. **取り込みの画面の横はみ出し**(点検12番): スマホで「ログアウト」が切れる
