### OCRの安全設計(触るときの前提)
- AIには、Claude Haiku 4.5(`claude-haiku-4-5-20251001`)を使用。費用は納品書1枚あたり1円未満(約$0.005)。
- 読み取り結果は**自動では確定しない**。必ず人が画面で確認してから登録。
- 写真は保存しない(メモリ上でリサイズして読み取りに使うだけ)。
- 上限判定は、DBの関数 `begin_ocr_attempt`(行ロックで判定・加算)と `complete_ocr_success`。利用者本人は回数を**読むだけ**で書き換えられない(RLS)。
- 同時に大量送信しても、試行10回を超えて通ることはない(実DBで20並列を確認済み)。成功回数は、同時送信の場合に最大で試行上限の範囲まで超え得るが、費用は数十円以内なので許容している。
- 「玉」と「個」は同じ意味でも自動換算しない(誤換算より安全側)。

### バックログ(把握済みだが、今は直さないと決めたもの)

- **歩留まり率を後から変えると、過去の月の原価も静かに変わる**(2026-10-06に見送りを決定)
  - 何が起きるか: 歩留まり率は価格履歴の対象外で、食材の「今の値」しか持っていない。そのため後から変えると、過去の月を再計算する画面すべてで、過去の月の原価も変更後の歩留まり率で計算し直される。画面には何も注記が出ない
  - 対象の画面: 今見直すべきメニュー、FL比率、売上管理、値上げの効果追跡
  - 直すなら: 歩留まり率も価格と同じように履歴に記録し、月末時点の値で再現する
- **未計算のメニューでも、単価が分かる食材だけで既に目標原価率を超えている場合があることが、利用者に伝わらない**(2026-10-21に見送りを決定)
  - 何が起きるか: 単価未設定の食材を含むメニューは、超過判定・値上げ目安・並び順の対象から外している(「計算できていません」と表示)。ところが、単価が分かる食材の原価だけで目標を超えているメニュー(例: 売価1,000円で、分かる分の原価だけで350円=35% > 目標30%)は、未設定の食材の単価が何円であっても確実に目標超過だが、画面ではそのことが分からない
  - 対象の画面: メニュー一覧(上部の件数・状態バッジ)、今見直すべきメニュー、ダッシュボードの「値上げ検討」
  - 直すなら: 未計算のメニューのうち「分かる分だけで既に目標超過」のものに、「単価を設定する前から目標超過が確実です」等の注記を出す(件数・並び順の扱いは変えずに、注記だけ足す案)

## 5. 別PCでの作業手順(追加分)

環境づくりの基本は [setup-new-pc.md](setup-new-pc.md)。以下は、それに加えて必要なこと。

### 5-1. アプリ(Next.js)
```bash
git pull
npm install
# .env.local を用意(setup-new-pc.md の3を参照。ANTHROPIC_API_KEY も必要)
npm run dev
```
- `ANTHROPIC_API_KEY` は **ワークスペース指定のキー**でないと、400「anthropic-workspace-id」エラーになる。
- 検証(変更のたびに実行し、PASS/FAILで報告): `npm run build` / `npm run lint` / `npm test`(いまは226本)。
- **デプロイは手動**: `npx vercel --prod`(git pushだけでは本番に反映されない)。初回は `npx vercel login` と `npx vercel link --project genka --yes` が必要(チームは `ms-projects-c2005791`)。
- `supabase/migrations/` にSQLを足しても、DBには反映されない。Supabase の SQL Editor で実行して初めて有効(実行したかMahiroに必ず確認)。

### 5-2. LP(`landing/`)
```bash
cd landing
pnpm install --frozen-lockfile    # pnpm が無ければ: npm i -g pnpm
pnpm dev                          # 手元で確認(ポートは 8443)
pnpm build                        # dist/ を作る
pnpm ship                         # ビルド → 公開(Vercelの genkaru-lp プロジェクト)。※ `pnpm deploy` はpnpm自身の別コマンドなので使わない
node scripts/deploy.mjs --dry     # リンクの確認だけ(公開しない)
```
- pnpmが入っていない(`npm i -g pnpm` が権限エラーになる)PCでは、インストールせずに `npx -y pnpm ship` で公開できる(新PCで2026-09-26に確認済み)。`sudo` は使わない。
- 公開(アプリ・LPとも)はClaude Codeの安全機能で止められるため、コマンドはMahiroがターミナルで実行する。
- 文言・URL・フォームの差し替えは `landing/src/App.tsx` の冒頭(`APP_URL` / `CONTACT_URL`)と本文。
- 画像は `landing/public/screenshots/`。
- **`dist/` の中で `vercel link` を実行しない**。トークン入りの `.env.local` が作られ、公開物に混ざる恐れがある。`pnpm ship` は一時フォルダにコピーしてから行い、`.env.local` を消してから公開する(この仕組みのため)。
- 一時フォルダの削除で「EBUSY」の警告が出ることがあるが、無害(手動で消してよい)。
- `pnpm ship` の「公開」部分そのものは、別PCでは初回に一度、動作を確認すること(この手順の `--dry` までは確認済み、公開部分は従来と同じ `vercel --prod` を使うが、スクリプト経由では未実行)。
- LPのフォルダはアプリのビルド・lintの対象外(`tsconfig.json` と `eslint.config.mjs` で除外済み)。

### 5-3. LPのスクリーンショットを撮り直すとき
アプリの画面を営業用に撮る手順。**本番の共有データや、Mahiroのアカウントは使わない。**
1. 使い捨てのデモアカウントを作る: `node --env-file=.env.local scripts/demo/seed_demo.mjs <メール> <パスワード>`(店舗・食材・メニュー・売上・固定費を作成)。
2. 「値上げの影響額」を見せたい場合は、デモ内の食材に**単価変動の履歴を2本**(古い単価→新しい単価)入れ、売上を**現在の月**にも入れる(でないと月間影響額が¥0になる)。
3. 納品書のサンプル画像は `scripts/demo/make_invoice.mjs` で作る。
4. ローカルで `npm run dev` を起動し、Playwrightで撮影する(サイドバーを外して、画面の中身だけ切り取る。`nextjs-portal` の開発用バッジは非表示にする)。ログイン後の画面の中身は `main` の中にある(スクロールするのは `body` ではなく `main`)。
5. **撮影後、デモアカウントを必ず削除**し、「サンプル食堂」の店舗が0件・`tmp-`で始まるユーザーが0件であることを確認する。
- Playwrightはこのリポジトリの依存には入れていない(`npm i --no-save playwright` で一時的に入れ、スクリプトはプロジェクトフォルダの中に置いて実行し、終わったら消す。scratchなどプロジェクト外だとモジュールが見つからない)。

### 5-4. LPを検索に載せる手順(noindexを外す)
今はLPを**意図的に検索に載せていない**(2026-10-21時点)。外すのはSMTP設定が済み、モニターを受け入れられる状態になってから(Mahiroの指示で行う)。
1. `landing/.figma/make/site.json` の `"robots": { "index": false }` を `true` にする(変えるのはこの1か所だけ)。
   - これで次の2つが同時に切り替わる: ①HTMLの `<meta name="robots" content="noindex, nofollow">` が消える、②`robots.txt` が「`Disallow: /`(全体巡回禁止)」→「`Allow: /` + `Sitemap: https://www.genka-lens.com/sitemap.xml`」になる(どちらも `landing/vite.config.ts` が `site.json` から生成する)。
   - `sitemap.xml` は `index` の値に関係なく常に出力している(`site.json` の `siteUrl` から生成)。
2. `cd landing && pnpm build` のあと、`dist/robots.txt` に `Allow: /` があること、`dist/index.html` に `noindex` が無いことを確認する。
3. `pnpm ship` で公開し、本番で `curl https://www.genka-lens.com/robots.txt` と、トップページのHTMLに `noindex` が無いことを確認する。
4. Search Consoleで `https://www.genka-lens.com/sitemap.xml` を送信し、URL検査で `https://www.genka-lens.com/` の「インデックス登録をリクエスト」を押す。
- 正規URLは `https://www.genka-lens.com`(`genka-lens.com` は www へ転送)。変えるときは `site.json` の `siteUrl` を直す(canonical・og:url・sitemapが連動する)。

## 6. ハマりどころ・運用メモ

### このPCのClaude Codeのメモリ(別PCには引き継がれないため、ここに転記)
**インフラ(リージョン)**
- Supabaseは ap-southeast-2(Sydney)。Vercelの関数実行リージョンも `syd1`(Sydney)に揃えてある。東京だった頃は、リージョン不一致でDB 1回あたり150〜300msかかっていた(現在は24〜50ms)。
- Vercelのリージョン変更は、CLIでは直接できず、REST API(`PATCH /v9/projects/{id}`、`serverlessFunctionRegion`)で行った。
- Vercelプロジェクトを**CLI/APIで新規作成すると`framework`が`null`のまま**になり、Next.jsとして動かず全ルート404になることがある。作った直後にダッシュボードでフレームワークを確認する(LPのような静的サイトは問題なし)。

**サイドバーの先読み(prefetch)は「全リンク自動」にしない**
- `src/components/Sidebar.tsx` の `<Link>` は `prefetch={false}` のまま。代わりに、ホバーで1リンクだけ先読みする実装。
- 全リンクを自動先読みにすると、認証トークンの更新が競合して**画面遷移中に強制ログアウト**される不具合を本番で再現した。サーバー側では原理的に直せない。変える場合は、実機で連続ホバー・クリックを何度も試してから。

**性能計測の注意**
- Claude Code実行環境の回線は日本のモバイル回線経由で、ここから本番の速度を測ると、実際のPC・固定回線より悲観的に出る(TLS接続だけで250〜440ms)。数字だけで「遅い」と判断せず、バックエンド処理時間を個別に見て、Mahiro本人の実機の体感も確認する。

### 環境・操作まわり
- Windowsで `rm` の対象に**シェル変数を含めると安全確認で止まる**。固定のパスで書く。
- `npx vercel --prod` の出力に `"status": "error"` が出ても、デプロイ自体は成功していることがある(ヒント表示のJSON)。`npx vercel ls` で `Ready` を確認する。
- 開発サーバー(`npm run dev`)は、重いインストールを並行するとメモリ不足で落ちる。落ちたら、他の処理が終わってから再起動。
- Git Bashで `npm run dev &` を実行すると「完了」と表示されるが、サーバーは動き続けている。止めるときは、ポート3000のプロセスを停止する。
- 共有の市場テーブル(`market_price_observations`、`livestock_price_observations`)に、**偽データを書き込まない**。他のユーザーにも見えるため。
